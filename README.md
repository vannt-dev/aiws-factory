**Language:** English · [Tiếng Việt](README.vi.md)

AIWS turns a requirement into tested code in an existing system that spans several repositories, and a person
approves the design before any code is written. Each target repository (frontend, backend, or any other side
you add) sits in its own `source-*` folder, as a plain folder or a git submodule; with submodules, each task
is committed in the repository it changes and, when pull requests are enabled, a draft pull request opens in
every repository that changed. An old system can sit beside them in `source-legacy/`, read-only.
`aiws discover` first builds a knowledge base from that code, and the analysis of each requirement works from it.
The design approval is recorded against the design files: if they change afterwards, the run stops until the
design is approved again.

Each requirement goes through controlled phases with human gates:
analysis → design + test spec → AI design review → **human approval** → per-task implementation with unit tests → review → **human PR merge** → knowledge update.
A deterministic orchestrator owns the state; AI agents only work inside the write scope of the current phase.
V1 runs on Claude Code and works with any language in the frontend, backend or legacy code.

**Landing page:** https://vannt-dev.github.io/aiws-factory/

## Workspace layout

```
requirements/         input requirements (written by people)
source-fe/            target frontend repository (any language)
source-be/            target backend repository (any language)
source-legacy/        legacy system, read-only
aiws/                 rules, agents, skills, templates, knowledge, work, orchestrator CLI
AGENTS.md             rules shared by every AI tool
CLAUDE.md, .claude/   generated by `aiws sync claude`, do not edit by hand
.codex/, .opencode/, .agents/   generated by `aiws sync codex|opencode|antigravity`, when you use those tools
```

## Quick start

Requirements: Node.js ≥ 22, Git, and Claude Code signed in. Works on **Windows, macOS and Linux** (all three run in CI);
build/test commands can differ per OS (`{windows: ..., posix: ...}` in `policies.yaml`).

```bash
npm install -g aiws-factory   # the `aiws` command, with the kit of this release; or from a clone of this repository:
                              #   cd aiws/adapters/cli && npm install && npm link && cd ../../..
aiws init my-project && cd my-project && git init   # a new workspace (skip inside a clone: the repository is one)
aiws detect --write      # recognise the stack of each source-* folder
aiws sync claude         # generate CLAUDE.md and .claude/
aiws sync opencode       # or codex, antigravity: the same agents, skills and guard for that tool
aiws discover            # build aiws/knowledge/
aiws new REQ-001 && aiws run REQ-001   # requirements/REQ-001-*.md first, or: aiws new REQ-001 --from-issue 12
aiws abandon REQ-001 -m "no longer needed"   # human-only: drop a requirement that will not be finished (status abandoned)
```
